Java & Spring Boot 25 questions

1. What is the difference between JDK, JRE and JVM?

The JVM runs bytecode. The JRE is the JVM plus core libraries. The JDK is the JRE plus developer tools such as javac.

2. What is the difference between == and .equals()?

== compares references (or primitive values). .equals() compares logical content when a class overrides it, as String does.

3. Why are Strings immutable, and what does that give you?

It makes them thread-safe, cacheable in the String pool, and reliable as HashMap keys and in security-sensitive values.

4. Abstract class vs interface?

An abstract class shares state and code, with single inheritance. An interface defines a contract or capability, a class can implement many, and it has default methods but no instance state.

5. Checked vs unchecked exceptions?

Checked exceptions (IOException) must be handled or declared and are usually recoverable. Unchecked ones (RuntimeException subclasses such as NullPointerException) usually signal programming errors.

6. ArrayList vs LinkedList?

ArrayList is array-backed with O(1) random access. LinkedList is node-based with O(n) access. ArrayList is the default choice in almost all cases.

7. How does a HashMap work, and what are the equals/hashCode rules?

hashCode() picks a bucket and equals() finds the key within it. Equal objects must return equal hash codes, and keys should be immutable.

8. HashMap vs LinkedHashMap vs TreeMap?

HashMap is unordered, LinkedHashMap keeps insertion order, and TreeMap keeps keys sorted with O(log n) operations.

9. What are Streams?

Declarative, lazy pipelines over collections: filter selects, map transforms, and a terminal operation such as collect runs the pipeline.

10. What is Optional, and when should you avoid it?

It models a possibly-absent return value. Avoid it for fields, method parameters and collections, and never call get() without checking.

11. final vs finally vs finalize?

final means constant, non-overridable or non-extendable. finally is a block that always runs after try. finalize is a deprecated pre-GC hook you should not use.

12. Overloading vs overriding?

Overloading is the same name with different parameters, resolved at compile time. Overriding is a subclass redefining a method, resolved at runtime (polymorphism).

13. How does garbage collection work at a high level?

The GC reclaims heap objects that are no longer reachable from GC roots. Generational collectors such as G1 collect short-lived objects often and old objects rarely.

14. What does @SpringBootApplication combine?

@Configuration, @EnableAutoConfiguration and @ComponentScan.

15. What is auto-configuration?

Boot inspects the classpath, properties and existing beans, then registers sensible defaults via @Conditional rules. Your own beans take precedence.

16. What is dependency injection, and why prefer constructor injection?

The container supplies dependencies instead of the class creating them. Constructor injection makes them explicit, allows final fields, and lets you test without Spring.

17. Component vs Service vs Repository vs Controller?

All register beans. @Service marks business logic, @Repository marks persistence (and adds exception translation), @Controller marks the web layer, and @Component is generic.

18. @RestController vs @Controller?

@RestController is @Controller plus @ResponseBody, so return values are written as JSON instead of resolved as view names.

19. How do you externalise configuration?

Use application.properties or YAML. Profile files such as application-dev.yml (selected with spring.profiles.active) override per environment, and environment variables override files.

20. @RequestParam vs @PathVariable vs @RequestBody?

@RequestParam reads query parameters (?id=1). @PathVariable reads URI segments (/users/{id}). @RequestBody deserialises the body (JSON) into an object.

21. How do you handle exceptions globally?

Use a @RestControllerAdvice class with @ExceptionHandler methods that map exceptions to consistent status codes and error bodies.

22. How do you validate request input?

Add spring-boot-starter-validation, annotate DTO fields (@NotBlank, @Size) and use @Valid on the @RequestBody. Failures produce a 400 response.

23. What is Spring Data JPA?

It generates repository implementations at runtime. JpaRepository gives CRUD, paging, sorting and derived queries such as findByEmail.

24. What is Actuator?

It exposes operational endpoints: /actuator/health, /info, /metrics and more. Use health for probes, and expose and secure only what you need.

25. Unit vs integration tests in Spring Boot?

Unit tests use plain JUnit and Mockito. @WebMvcTest with @MockBean tests the web layer in isolation. @SpringBootTest loads the full context, optionally with Testcontainers for a real database.

Microservices 25 questions

1. What is a microservice, and how does it differ from a monolith?

A small, independently deployable service that owns one business capability and its data. A monolith is built and deployed as one unit.

2. Advantages and disadvantages?

Pros: independent deploys and scaling, fault isolation, technology choice. Cons: distributed-system complexity, network latency, data consistency and operational overhead.

3. How do you decide service boundaries?

Around business capabilities or bounded contexts (DDD). If two services always change together, they probably belong together.

4. How do microservices communicate?

Synchronously via REST or gRPC (simple, but couples availability) or asynchronously via messaging such as Kafka or RabbitMQ (decoupled and buffered).

5. Why use an API Gateway?

A single entry point for routing, authentication, rate limiting and aggregation, so individual services don't each repeat that logic.

6. What is service discovery?

Finding service instances dynamically. Kubernetes provides DNS names per Service, while Eureka is a client-side registry.

7. What is a circuit breaker?

It wraps remote calls. After a failure threshold it opens and fails fast, then half-opens to test recovery (for example Resilience4j).

8. Retry vs timeout vs fallback?

A timeout bounds the wait, a retry re-attempts transient failures (with backoff), and a fallback returns a degraded default if the call still fails.

9. What is database per service?

Each service owns its schema, so services can evolve and scale independently. Other services access the data through APIs or events, not the database.

10. How do you handle transactions across services?

The Saga pattern: a series of local transactions with compensating actions on failure, coordinated by events (choreography) or a coordinator (orchestration).

11. What is eventual consistency?

Data across services converges over time instead of being instantly consistent, so logic and UX must tolerate temporary differences.

12. What is idempotency and why does it matter?

Repeating an operation gives the same result. Retries and message redelivery happen, so use idempotency keys or naturally idempotent operations.

13. How do you version a REST API?

Use a URI (/v1/) or header version, add fields backward-compatibly, and deprecate before removing.

14. How do you secure service calls?

Validate OAuth2/JWT tokens at the gateway and services, use mTLS or service tokens between services, apply least privilege and keep secrets in a vault.

15. What is centralised configuration?

Keeping config outside the artefact (Spring Cloud Config, Kubernetes ConfigMaps and Secrets) so it changes per environment without a rebuild.

16. What is distributed tracing?

A trace ID is propagated across calls and collected by OpenTelemetry or Micrometer Tracing, then viewed in Jaeger or Zipkin to follow one request end to end.

17. How do you approach logging and monitoring?

Structured logs with correlation IDs aggregated centrally (ELK, Loki), plus metrics (Prometheus, Grafana) and alerts on latency, errors and saturation.

18. Orchestration vs choreography?

Orchestration uses a central coordinator to direct steps. Choreography has services react to each other's events, which is more decoupled but harder to follow.

19. What are Kafka or RabbitMQ used for?

Asynchronous messaging: decoupling services, absorbing traffic spikes, event-driven workflows and reliable delivery.

20. What is the outbox pattern?

Write the business change and an event row in one database transaction. A separate process publishes the outbox rows, avoiding dual-write inconsistency.

21. How do you test a microservice?

Unit tests, component tests with mocks or Testcontainers, contract tests between services, and a small number of end-to-end tests.

22. What is consumer-driven contract testing?

Consumers define their expectations of a provider's API (Pact, Spring Cloud Contract) and the provider verifies them in CI to catch breaking changes.

23. What are health checks for?

Liveness and readiness endpoints tell the platform whether to restart an instance or route traffic to it. Readiness should reflect dependency availability.

24. How do you avoid cascading failures?

Timeouts, circuit breakers, bulkheads, rate limiting, backpressure and fallbacks, so one slow service doesn't exhaust others' threads.

25. When would you not use microservices?

For a small team, a simple domain or an early product. A modular monolith is cheaper and faster, and you can split later when needed.

Kubernetes 25 questions

1. What does Kubernetes solve compared with docker run?

Docker runs a container. Kubernetes adds scheduling across nodes, self-healing, scaling, rolling updates and service discovery.

2. What are the main cluster components?

Control plane: API server, etcd, scheduler, controller manager. Worker nodes: kubelet, kube-proxy and a container runtime.

3. What is a Pod?

One or more tightly coupled containers sharing network and storage. Kubernetes schedules Pods, not bare containers.

4. Pod vs Deployment?

A Pod is a single running instance. A Deployment declares the desired replicas and manages Pods through ReplicaSets, giving self-healing and rolling updates.

5. What is a ReplicaSet?

It ensures a specified number of identical Pod replicas is running. Each Deployment revision gets its own ReplicaSet.

6. What is a Service?

A stable virtual IP and DNS name that load-balances across Pods matching a selector, because Pod IPs change.

7. ClusterIP vs NodePort vs LoadBalancer?

ClusterIP is internal only. NodePort opens a port on every node. LoadBalancer provisions an external cloud load balancer.

8. What is a Namespace?

A logical partition for isolating teams or environments, with scoped names, quotas and RBAC.

9. What are labels and selectors?

Labels are key-value tags on objects and selectors match on them. A Service routes to Pods whose labels match its selector.

10. What is a ConfigMap?

Non-secret configuration as key-value pairs, injected into Pods as environment variables or mounted files.

11. Secret vs ConfigMap?

Secrets hold sensitive data but are only base64-encoded by default. Enable encryption at rest and RBAC, or use an external secret store.

12. Requests vs limits?

Requests are what the scheduler reserves. Limits are the cap. Set both so Pods schedule sensibly and can't starve their neighbours.

13. What happens when a container exceeds its memory limit?

It is killed (OOMKilled, exit code 137) and restarted. Exceeding the CPU limit only throttles it.

14. Liveness vs readiness vs startup probes?

Liveness restarts an unhealthy container. Readiness gates traffic. Startup gives slow-starting apps time before the other probes begin.

15. How does a rolling update work, and how do you roll back?

Pods are replaced gradually (maxSurge, maxUnavailable). Watch with kubectl rollout status and revert with kubectl rollout undo.

16. How do you scale?

Manually with kubectl scale deployment <name> --replicas=3. The Horizontal Pod Autoscaler adjusts replicas automatically from metrics such as CPU.

17. What does kubectl describe pod show that get doesn't?

Events, conditions, restart reasons, probe failures and scheduling details, which is where most diagnoses start.

18. How do you debug CrashLoopBackOff?

Run kubectl describe pod and kubectl logs <pod> --previous. Look for startup errors, missing config, failing probes or OOM, then fix and redeploy.

19. What causes ImagePullBackOff?

A wrong image name or tag, missing registry credentials (imagePullSecrets), or an unreachable registry. describe shows the exact error.

20. What does a Pending Pod usually mean?

The scheduler can't place it: insufficient CPU or memory, unmatched node selectors or taints, or an unbound PVC. Events explain which.

21. Ingress vs Service?

An Ingress defines HTTP(S) host and path routing, served by an ingress controller, giving one entry point for many Services. A Service exposes a single workload.

22. What are PV and PVC?

A PersistentVolume is storage in the cluster. A PersistentVolumeClaim is a Pod's request for it, which decouples provisioning from use.

23. Deployment vs StatefulSet vs DaemonSet?

Deployment: interchangeable stateless replicas. StatefulSet: stable identities and storage. DaemonSet: one Pod per node, such as a logging agent.

24. How does DNS-based discovery work?

CoreDNS resolves service.namespace.svc.cluster.local to the Service IP, so Pods can call each other by name.

25. kubectl apply vs create?

create fails if the object exists (imperative). apply creates or updates from declarative manifests and is preferred.

Containerization 25 questions

1. What is a container, and how does it differ from a VM?

Containers share the host kernel and isolate processes, so they are lightweight and start fast. VMs run a full guest OS.

2. Image vs container?

An image is an immutable layered template. A container is a running (or stopped) instance of it with a writable layer.

3. What is a registry and why is it needed?

A storage and distribution service for images (Docker Hub, ACR), so other machines can pull what you built.

4. What are image layers and caching?

Each instruction creates a read-only layer, and unchanged layers are cached. Put stable steps such as dependencies first and volatile ones last.

5. Walk through a Spring Boot Dockerfile.

FROM sets a JRE base, WORKDIR sets the directory, COPY adds the JAR, EXPOSE 8080 documents the port and ENTRYPOINT runs java -jar.

6. CMD vs ENTRYPOINT?

ENTRYPOINT is the fixed executable. CMD supplies default arguments that docker run can override.

7. COPY vs ADD?

COPY copies local files. ADD also extracts archives and fetches URLs, so prefer COPY for clarity.

8. EXPOSE vs -p?

EXPOSE only documents the port. -p host:container actually publishes it.

9. What is a multi-stage build?

Build in a JDK/Maven stage, then copy only the JAR into a slim JRE stage. The result is a smaller, safer image without build tools.

10. Why a JRE or slim base image?

Smaller size, faster pulls and a reduced attack surface. A JRE is enough to run a JAR.

11. What is .dockerignore?

It excludes files (target/, .git) from the build context, speeding builds and avoiding leaked secrets.

12. How do image tags work?

Tags label versions. latest is mutable and unpredictable, so use explicit version tags (or digests) for reproducible deployments.

13. Volume vs bind mount?

A volume is managed by Docker and portable. A bind mount maps a specific host path, which is handy in development.

14. How do you pass configuration into a container?

-e KEY=value, --env-file or mounted config files. In Kubernetes, use ConfigMaps and Secrets.

15. How do containers communicate on one host?

On a user-defined bridge network they resolve each other by name. The default bridge needs IPs.

16. docker stop vs docker kill?

stop sends SIGTERM, then SIGKILL after a grace period. kill sends SIGKILL immediately (or a chosen signal).

17. How do you view logs or get a shell?

docker logs -f <container> and docker exec -it <container> sh.

18. What does the writable layer imply for persistence?

It is deleted with the container, so persist data in volumes or external services.

19. Why not run as root?

A compromised root process is more dangerous. Add a non-root user with USER and run with least privilege.

20. How do you keep secrets out of images?

Never bake them into layers or ARGs. Inject at runtime through environment variables or secret stores, and use BuildKit secrets at build time.

21. How do you reduce image size?

Use slim or distroless bases, multi-stage builds, fewer layers, clean package caches and a .dockerignore.

22. What is Docker Compose?

It defines and runs multi-container apps from a YAML file (docker compose up), useful locally for an app plus its database.

23. How do you tune the JVM for containers?

Modern JVMs are container-aware. Set -XX:MaxRAMPercentage=75 (or -Xmx) so the heap fits inside the memory limit.

24. How do you scan images for vulnerabilities?

Use Trivy, Grype or Docker Scout in CI, keep base images updated and fail builds on critical CVEs.

25. A container exits immediately. How do you investigate?

Check docker ps -a for the exit code and docker logs for errors. Common causes are a main process that ends, a startup crash or a wrong ENTRYPOINT/CMD. Override the entrypoint with sh to explore.
