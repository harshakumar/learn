2. React / Frontend

“How many years of React experience do you have?”I’ve been working with React for about [X] years, alongside [X] years of Java, so I’m comfortable working full stack.

“What kind of applications have you built with React?”I’ve built a range of things — customer-facing dashboards, admin/internal tools, and data-heavy interfaces with tables, filters, and real-time updates. “Have you worked with TypeScript?”Yes, I’ve used TypeScript on most recent React projects — it’s made a real difference in catching bugs early and making larger codebases easier to maintain, especially with shared interfaces between frontend and backend DTOs.

“Have you used Redux or another state-management library?”Yes, I’ve used Redux for global state in larger applications, and more recently I’ve leaned on React Context and hooks like useReducer for lighter-weight cases where a full Redux setup wasn’t necessary.

“Have you worked with reusable components?”Yes, I’ve built and maintained shared component libraries — form inputs, tables, modals — to keep UI consistent and reduce duplication across teams.

“Have you worked with React testing?”Yes, I use Jest and React Testing Library for unit and component tests, and I’ve used Cypress for end-to-end testing on a couple of projects.

8. Your Question for Them

Don’t end with “No, I think that’s everything.” Ask something that signals seniority:

“Could you tell me a little more about the team, the type of applications they’re currently building, and what you’re looking for from the person joining this role in the first six months?”

Optional follow-ups if there’s time: - “What does the tech stack look like beyond Java and React — any plans to evolve it?” - “How is the team structured, and who would I be working most closely with?” - “What’s the biggest technical challenge the team is facing right now?”

Tip for the actual mock call: read through this once, then close the doc and answer out loud from memory in your own words — reading verbatim will sound scripted on a real call.
