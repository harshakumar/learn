Java & Spring Boot: Detailed Answers

25 questions with in-depth model answers, code examples and interview tips. Try answering aloud before opening each one.

1. What is the difference between JDK, JRE and JVM?

The JVM executes bytecode and provides memory management, garbage collection and the JIT compiler. It is platform-specific, which is why the same bytecode runs anywhere. The JRE is the JVM plus the standard class libraries (java.lang, java.util, and so on). The JDK is the JRE plus developer tools: javac, jar, jshell, javadoc, jlink and debuggers.

The flow is: .java source, then javac, then .class bytecode, then the JVM (which interprets it and JIT-compiles hot code to native).

Tip: mention containers. Since Java 11 there is no standalone JRE download, but images such as eclipse-temurin:17-jre ship a runtime only, which keeps deployment images small.

2. What is the difference between == and .equals()?

== compares references for objects (and values for primitives). Object.equals() also compares references by default, but classes such as String, Integer and records override it to compare content.

String a = "hi";
String b = "hi";
String c = new String("hi");
a == b;       // true  (both from the String pool)
a == c;       // false (different objects)
a.equals(c);  // true  (same content)

If you override equals() you must override hashCode() too. Use Objects.equals(x, y) for null-safe comparison.

Tip: never compare boxed Integer values with ==. It only works by accident inside the cached range -128 to 127.

3. Why are Strings immutable, and what does that give you?

Once created, a String can't change. This gives you four things:

Security: values such as class names, URLs and credentials can't be altered after validation. Thread safety: immutable objects can be shared freely without locking. Pooling: identical literals share one object in the String pool, saving memory. Hashing: the hash code can be cached, which makes Strings fast and safe as HashMap keys.

The cost is that repeated concatenation in a loop creates many temporary objects. Use StringBuilder there (StringBuffer is the older synchronised version).

4. What is the difference between an abstract class and an interface?

An abstract class can hold instance state, constructors and methods with any access level, but a class can extend only one. An interface describes a capability: a class can implement many, and since Java 8 interfaces can have default, static and (Java 9) private methods, but no instance fields.

Use an abstract class when related classes share state or a common implementation (AbstractList). Use an interface for a contract that unrelated classes can fulfil (Comparable, Runnable). Interfaces are usually preferred for public APIs because they don't lock callers into an inheritance hierarchy. Java 17 also adds sealed types to restrict who may implement or extend.

5. Explain checked vs unchecked exceptions, with an example of each.

Throwable splits into Error (JVM problems such as OutOfMemoryError) and Exception. Checked exceptions (IOException, SQLException) extend Exception directly and must be caught or declared with throws. Unchecked exceptions extend RuntimeException (NullPointerException, IllegalArgumentException) and the compiler doesn't force handling.

Use checked for recoverable conditions the caller can act on, and unchecked for programming errors or unrecoverable failures. Modern frameworks such as Spring favour unchecked exceptions.

Tip: a classic follow-up. By default, @Transactional rolls back on unchecked exceptions only, not on checked ones, unless you set rollbackFor.

6. What is the difference between ArrayList and LinkedList?

ArrayList is backed by a resizable array (it grows by about 50%). Access by index is O(1), appending is amortised O(1), and inserting or removing in the middle is O(n) because elements shift. LinkedList is a doubly linked list. Access by index is O(n), and insert or remove is O(1) only once you already hold the node or iterator.

In practice ArrayList almost always wins, even for many inserts, because contiguous memory is cache-friendly and nodes carry extra object overhead. For a queue or stack, use ArrayDeque rather than LinkedList.

7. How does a HashMap work internally, and what are the equals/hashCode rules for keys?

A HashMap is an array of buckets (default 16, doubling when it passes the 0.75 load factor). To put a key, Java computes hashCode(), spreads the bits, and picks a bucket with hash & (n-1). Colliding keys chain in that bucket, and from Java 8 a bucket with 8 or more entries (in a large enough table) becomes a red-black tree, so worst-case lookup is O(log n). get finds the bucket by hash and then uses equals() to find the right key.

The contract: equal objects must have equal hash codes. Keys should be immutable, because changing a key's fields after insertion means it is looked up in the wrong bucket. HashMap isn't thread-safe. Use ConcurrentHashMap for concurrent access.

8. What is the difference between HashMap, LinkedHashMap and TreeMap?

HashMap: no ordering guarantee, O(1) average operations, allows one null key. LinkedHashMap: a HashMap plus a linked list through the entries, so iteration follows insertion order (or access order, which makes a simple LRU cache possible by overriding removeEldestEntry). TreeMap: a red-black tree keeping keys sorted by natural order or a Comparator, O(log n) operations, no null keys, plus navigation methods such as firstKey, floorKey and headMap.

Choose HashMap by default, LinkedHashMap when order matters, and TreeMap when you need sorted keys or range queries.

9. What are Java Streams, and how do map, filter and collect work?

A stream is a lazy pipeline over a data source, not a data structure. Intermediate operations (filter, map, sorted) build the pipeline and do nothing until a terminal operation (collect, forEach, reduce, count) runs it. A stream can only be consumed once.

List<String> result = users.stream()
    .filter(u -> u.isActive())
    .map(User::getName)
    .sorted()
    .toList();               // Java 16+

Map<String, List<User>> byCity =
    users.stream().collect(Collectors.groupingBy(User::getCity));

Avoid side effects and mutating the source inside a stream. Use parallel streams only for large, CPU-bound work, since they share the common fork-join pool.

10. What is Optional, and when should you avoid it?

Optional<T> makes "might be absent" explicit in a return type, so callers can't forget the empty case.

String name = repo.findById(id)
    .map(User::getName)
    .orElseThrow(() -> new NotFoundException(id));

orElse(x) always evaluates x, whereas orElseGet(() -> x) evaluates it only when empty, so prefer the latter for expensive defaults.

Avoid it for fields, method parameters and collection returns (return an empty list instead). It isn't serialisable, and calling get() without checking just moves the NullPointerException.

11. What is the difference between final, finally and finalize?

final on a variable means it can't be reassigned, on a method it can't be overridden, and on a class it can't be subclassed. finally is a block after try/catch that runs whether or not an exception occurred (except after System.exit or a JVM crash), typically for cleanup. Never return inside finally, because it overrides the real result. finalize() was an object hook called before garbage collection. It is deprecated for removal because it is unpredictable and slow. Use try-with-resources (AutoCloseable) or Cleaner instead.

12. Explain method overloading vs overriding.

Overloading means the same method name with different parameter lists in one class, chosen at compile time from the argument types (like println(int) and println(String)). Overriding means a subclass provides its own version of an inherited method, chosen at runtime from the object's actual type. That is polymorphism.

Overriding rules: same signature, a return type that is the same or a subtype, access no weaker than the parent's, and no broader checked exceptions. Always add @Override so the compiler catches typos. static and private methods can be hidden but not overridden.

13. How does garbage collection work at a high level?

The GC frees objects that are no longer reachable from GC roots (thread stacks, static fields). Most objects die young, so the heap is generational: new objects go to Eden, survivors move through survivor spaces, and long-lived ones are promoted to the old generation. Young collections are frequent and cheap, and old collections are rarer and costlier.

G1 has been the default since Java 9. It splits the heap into regions and targets a pause-time goal. ZGC and Shenandoah aim for very low pauses. Java "memory leaks" are usually lingering references, such as growing static maps or unremoved listeners. Diagnose with GC logs (-Xlog:gc), jstat and heap dumps. In containers, size the heap with -XX:MaxRAMPercentage.

14. What does @SpringBootApplication combine?

Three annotations: @Configuration (the class can declare beans), @EnableAutoConfiguration (Boot configures beans based on the classpath) and @ComponentScan (finds @Component, @Service and so on).

The scan starts at the main class's package and goes downwards, so put the main class in the root package or your beans won't be found. SpringApplication.run() creates the ApplicationContext and starts the embedded server (Tomcat by default). You can opt out of specific auto-configurations with @SpringBootApplication(exclude = DataSourceAutoConfiguration.class).

15. What is auto-configuration, and how does Spring Boot decide what to configure?

The spring-boot-autoconfigure jar lists many candidate configuration classes in an AutoConfiguration.imports file. Each is guarded by conditions such as @ConditionalOnClass (a library is on the classpath), @ConditionalOnMissingBean (you haven't defined your own) and @ConditionalOnProperty.

For example, with spring-boot-starter-web on the classpath, Boot configures Tomcat, Jackson and Spring MVC. If you define your own DataSource bean, the default one backs off. Run with --debug (or use the Actuator conditions endpoint) to see which configurations matched and why.

16. What is dependency injection, and why is constructor injection preferred over field injection?

With dependency injection (inversion of control) the container creates objects and supplies their collaborators, instead of each class building its own.

@Service
public class OrderService {
    private final PaymentClient payments;
    public OrderService(PaymentClient payments) {   // no @Autowired needed
        this.payments = payments;
    }
}

Constructor injection makes dependencies explicit and required, allows final fields (immutability), works in plain unit tests (new OrderService(mock)), and exposes circular dependencies at startup. Field injection hides dependencies and needs reflection to test.

17. What is the difference between @Component, @Service, @Repository and @Controller?

All are stereotype annotations meta-annotated with @Component, so all register a bean during scanning. The differences are semantic and tooling-related.

@Service marks business logic (no extra behaviour, but a good AOP target). @Repository marks data access and enables exception translation, turning vendor exceptions into Spring's DataAccessException. @Controller marks a web layer class, handled by Spring MVC. @Component is the generic fallback. Using the specific stereotype documents intent and lets pointcuts target a layer.

18. What is the difference between @RestController and @Controller?

@RestController is @Controller plus @ResponseBody. Return values are written straight to the HTTP response body through message converters (Jackson for JSON), instead of being treated as view names.

@RestController
@RequestMapping("/users")
class UserController {
    @GetMapping("/{id}")
    ResponseEntity<User> get(@PathVariable Long id) {
        return ResponseEntity.ok(service.find(id));
    }
}

A plain @Controller is for server-rendered pages (for example Thymeleaf), where a returned "home" resolves to a template. Return ResponseEntity when you need control over status codes and headers.

19. How do you externalise configuration using application.properties/yml and profiles?

Settings live outside the code so one build runs in every environment. Precedence, highest first: command-line arguments, environment variables, profile-specific files (application-prod.yml), then application.yml. Activate a profile with spring.profiles.active=prod or SPRING_PROFILES_ACTIVE.

Prefer type-safe binding over scattered @Value:

@ConfigurationProperties(prefix = "app.payment")
public record PaymentProps(String baseUrl, Duration timeout) {}

Environment variables bind via relaxed naming (SPRING_DATASOURCE_URL maps to spring.datasource.url), which is how Kubernetes ConfigMaps and Secrets feed the app. Never commit secrets.

20. How do @RequestParam, @PathVariable and @RequestBody differ?
@GetMapping("/orders/{id}")            // GET /orders/42?expand=true
Order get(@PathVariable Long id,
          @RequestParam(defaultValue = "false") boolean expand) {...}

@PostMapping("/orders")                // JSON body
Order create(@RequestBody @Valid OrderRequest req) {...}

@PathVariable binds a segment of the URL path and identifies a resource. @RequestParam binds query or form parameters, which suit filters and paging, and can be optional or have defaults. @RequestBody deserialises the request body (usually JSON, via Jackson) into an object and requires a matching Content-Type. @RequestHeader reads headers.

21. How would you handle exceptions globally in a REST API?

Centralise them in a @RestControllerAdvice:

@RestControllerAdvice
class ApiErrors {
    @ExceptionHandler(NotFoundException.class)
    ProblemDetail notFound(NotFoundException ex) {
        return ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
    }
}

ProblemDetail (Spring 6 / Boot 3) implements the standard RFC 7807 error format. Also handle MethodArgumentNotValidException for validation errors, and add a catch-all handler that logs the stack trace server-side but returns a generic message, so internals never leak to clients.

22. How do you validate request input in Spring Boot?

Add spring-boot-starter-validation, annotate the DTO, and trigger validation with @Valid:

public record SignupRequest(
    @NotBlank String name,
    @Email String email,
    @Min(18) int age) {}

@PostMapping("/signup")
void signup(@RequestBody @Valid SignupRequest req) {...}

A failure throws MethodArgumentNotValidException, which you map to a 400 response listing field errors in your global handler. Use @Validated on the class to validate path and query parameters, and write custom constraints for business rules. Validate at the API boundary, and don't rely on it in place of database constraints.

23. What is Spring Data JPA, and what does JpaRepository give you?

You declare an interface and Spring generates the implementation at runtime (Hibernate is the usual JPA provider).

public interface UserRepository extends JpaRepository<User, Long> {
    Optional<User> findByEmail(String email);            // derived query
    @Query("select u from User u where u.city = :c")
    List<User> inCity(@Param("c") String city);
}

JpaRepository gives CRUD (save, findById, deleteById), paging and sorting (Pageable), and derived queries from method names. Watch for the N+1 select problem (fix with fetch joins or entity graphs), keep @Transactional on the service layer, and expose DTOs rather than entities.

24. What is Spring Boot Actuator, and which endpoints would you use in production?

Actuator adds production-ready endpoints for monitoring. The key ones are /actuator/health, /actuator/info, /actuator/metrics and /actuator/prometheus (via Micrometer).

Expose only what you need (management.endpoints.web.exposure.include=health,info,prometheus) and secure the rest, ideally on a separate management port. Health groups provide /actuator/health/liveness and /actuator/health/readiness, which map directly onto Kubernetes probes. You can add custom checks by implementing HealthIndicator.

25. How do you write a unit test vs an integration test in Spring Boot?

Unit test: plain JUnit 5 and Mockito, no Spring context, so it is fast.

@ExtendWith(MockitoExtension.class)
class OrderServiceTest {
    @Mock PaymentClient payments;
    @InjectMocks OrderService service;
}

Slice test: @WebMvcTest(UserController.class) with MockMvc and a mocked service (@MockBean, or @MockitoBean from Boot 3.4) tests only the web layer. @DataJpaTest does the same for repositories. Integration test: @SpringBootTest loads the full context, ideally with Testcontainers for a real database. Keep most tests at the fast end of that spectrum.
